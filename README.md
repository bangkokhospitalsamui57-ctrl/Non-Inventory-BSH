# Non Inventory System — ระบบเบิกของใช้ฟุ่มเฟือย
Bangkok Hospital Samui

เวอร์ชันนี้เป็นไฟล์ HTML/JS ธรรมดา (ไม่ผูกกับ Claude) พร้อมสำหรับฝากไว้บน **GitHub Pages**
และใช้ **Google Sheet** เป็นฐานข้อมูล (ผ่าน Google Apps Script ที่ทำหน้าที่เป็น JSON API)

## โครงสร้างไฟล์
```
index.html          หน้าเว็บหลัก (โครงสร้าง + CSS + ข้อมูลสินค้า/แผนกเริ่มต้น + โลโก้ ฝังอยู่ในไฟล์นี้)
config.js           ใส่ลิงก์ Apps Script Web App ของคุณที่นี่
app.js              โค้ดโปรแกรมทั้งหมด (ล็อกอิน, เบิก/เติมสต๊อก, รายงาน, จัดการผู้ใช้ ฯลฯ)
apps-script/Code.gs โค้ดฝั่ง Google Apps Script (ตัวฐานข้อมูล/ API)
```

## วิธีติดตั้ง (ทำครั้งเดียว)

### ขั้นตอนที่ 1 — สร้างฐานข้อมูลด้วย Google Sheet
1. ไปที่ [sheets.google.com](https://sheets.google.com) สร้างชีตใหม่ 1 ไฟล์ ตั้งชื่ออะไรก็ได้ เช่น "NIS Database"
2. เมนู **ส่วนขยาย (Extensions) > Apps Script**
3. ลบโค้ดตัวอย่างที่มีอยู่ แล้ววางโค้ดทั้งหมดจากไฟล์ `apps-script/Code.gs` ลงไปแทน
4. กด **Deploy > New deployment**
   - เลือกประเภท (Select type) เป็น **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
5. กด **Deploy** แล้วกด **Authorize access** ยืนยันสิทธิ์การเข้าถึงบัญชี Google ของคุณ
6. คัดลอกลิงก์ **Web app URL** ที่ได้ (จะลงท้ายด้วย `/exec`)

> ทุกครั้งที่แก้ไขโค้ดใน Apps Script ภายหลัง ต้องกด **Deploy > Manage deployments > แก้ไข (ไอคอนดินสอ) > Version: New version > Deploy** ใหม่ทุกครั้ง ไม่งั้นการแก้ไขจะไม่มีผล

> **ถ้าเคยวางโค้ด Code.gs เวอร์ชันเก่า (ที่มีแท็บ "DB" เดียว) ไปแล้ว**: วางโค้ดใหม่ทับของเดิมได้เลย แล้ว Deploy เวอร์ชันใหม่ตามปกติ — เวอร์ชันใหม่จะสร้างแท็บ products / requisitions / auth_users แยกให้เอง (ถ้ามีข้อมูลจริงอยู่ในแท็บ "DB" เดิมแล้วไม่อยากเสีย แจ้งมาได้ ช่วยเขียนสคริปต์ย้ายข้อมูลให้)

### ขั้นตอนที่ 2 — ตั้งค่าไฟล์เว็บให้ชี้ไปที่ฐานข้อมูล
เปิดไฟล์ `config.js` แล้ววางลิงก์ที่ได้จากขั้นตอนที่ 1 แทนข้อความ `PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE`:
```js
window.NIS_CONFIG = {
  API_URL: "https://script.google.com/macros/s/xxxxxxxxxxxxxxxxxxxx/exec"
};
```

### ขั้นตอนที่ 3 — ฝากไฟล์ไว้บน GitHub Pages
1. สร้าง repository ใหม่บน GitHub (public หรือ private ก็ได้ ถ้า private ต้องมี GitHub Pro ถึงจะเปิด Pages ได้)
2. อัปโหลดไฟล์ทั้ง 3 ไฟล์ (`index.html`, `config.js`, `app.js`) ไว้ที่ root ของ repo (โฟลเดอร์ `apps-script/` ไม่จำเป็นต้องอัปโหลดขึ้นเว็บ เก็บไว้อ้างอิงก็พอ)
3. ไปที่ **Settings > Pages** เลือก Branch เป็น `main` โฟลเดอร์ `/ (root)` แล้วกด Save
4. รอสักครู่ จะได้ลิงก์เว็บรูปแบบ `https://<username>.github.io/<repo>/`
5. เปิดลิงก์นั้น ล็อกอินด้วยบัญชีทดลอง (ดูด้านล่าง) — ระบบจะสร้างข้อมูลสินค้าเริ่มต้นและบัญชีทดลองลงใน Google Sheet ให้อัตโนมัติในการโหลดครั้งแรก

## บัญชีเริ่มต้น (สร้างอัตโนมัติในการโหลดครั้งแรก)
- แอดมิน: `admin` / `admin123`
- ผู้ใช้งานทั่วไป: `staff` / `staff123`

**สำคัญ:** รายชื่อพนักงาน 415 คนที่นำเข้าไว้ในเวอร์ชัน Claude artifact ก่อนหน้านี้ **ไม่ได้ติดมาด้วย** เพราะเป็นคนละฐานข้อมูลกัน ต้องนำเข้าใหม่ในเวอร์ชันนี้ผ่านหน้า **ผู้ใช้งาน (แอดมิน) > นำเข้ารายชื่อพนักงานหลายคนพร้อมกัน** โดยวางข้อมูลรูปแบบ `รหัสพนักงาน,ชื่อ-นามสกุล` ทีละบรรทัด (ถ้าต้องการไฟล์ CSV ที่แปลงจากไฟล์ Excel ที่เคยส่งมา แจ้งได้ครับ จะจัดให้)

## ฐานข้อมูลใน Google Sheet อ่านง่าย (ไม่ใช่ไฟล์ JSON บีบอัด)
ระบบสร้างแท็บ (sheet) แยกให้อัตโนมัติทีละคอลเลกชัน เปิดดูตรงๆ ในชีตได้เลย เป็นตารางปกติ ไม่ต้องแปลข้อมูล:
- แท็บ **products** — รหัสสินค้า, ชื่อ, หมวดหมู่, หน่วย, ราคา, คงเหลือ, รูป (base64)
- แท็บ **requisitions** — วันที่, ประเภท, แผนก, ผู้เบิก, รหัสพนักงาน, ยอดรวม (คอลัมน์ `items` เก็บรายละเอียดรายสินค้าเป็น JSON เพราะเป็นรายการย่อยหลายชิ้นต่อ 1 ใบเบิก)
- แท็บ **auth_users** — รหัสพนักงาน (username), สิทธิ์, ชื่อที่แสดง, รหัสผ่านที่เข้ารหัสแล้ว (passwordHash)

แท็บเหล่านี้จะถูกสร้างอัตโนมัติพร้อมหัวตารางตั้งแต่ครั้งแรกที่แอปเขียนข้อมูล ไม่ต้องสร้างเองล่วงหน้า

## ดาวน์โหลดข้อมูลออกมาเป็นไฟล์
- **หน้ารายงานทุกหน้า** (ฟุ่มเฟือย, การเบิก, เติมสต๊อก, รายแผนก) และ **หน้าประวัติ** มีปุ่มดาวน์โหลดทั้ง **CSV** และ **Excel (.xlsx)** ให้เลือกได้ (เฉพาะแอดมิน) — ไฟล์ Excel เปิดใน Microsoft Excel ได้ตรงๆ ไม่มีปัญหาภาษาไทยเพี้ยนแบบ CSV บางโปรแกรม
- **หน้าผู้ใช้งาน (แอดมิน)** มีปุ่ม **"ดาวน์โหลดฐานข้อมูลทั้งหมด"** ทั้งแบบ **Excel** (ไฟล์เดียว 3 ชีต: สินค้าคงคลัง, ประวัติการทำรายการ, ผู้ใช้งาน — ไม่รวมรหัสผ่านที่เข้ารหัสไว้) และแบบ **JSON** (สำหรับสำรองข้อมูลดิบหรือย้ายระบบ)

## สรุปรายการเบิก — ตรวจสอบและปล่อยของ (เฉพาะแอดมิน)
พฤติกรรมการเบิกเปลี่ยนไปเล็กน้อยเพื่อรองรับการตรวจสอบก่อนปล่อยของจริง:
- เมื่อผู้ใช้กด **"บันทึกการเบิก"** ระบบจะ **ยังไม่ตัดสต๊อกทันที** — สร้างเป็น "คำขอเบิก" สถานะ **รอปล่อยของ** ก่อน
- แอดมิน/เจ้าหน้าที่คลังไปที่แท็บ **"📋 สรุปรายการเบิก"** (ตัวเลขในวงเล็บที่แท็บ = จำนวนคำขอที่รอดำเนินการ) จะเห็นคำขอทั้งหมดเรียงจากเก่าสุดก่อน
- แต่ละคำขอแสดงรายการสินค้าที่ขอเบิก เทียบกับ **จำนวนคงเหลือปัจจุบัน** และมีช่องให้ปรับ **"จำนวนที่จะปล่อยจริง"** ได้ก่อนยืนยัน (เผื่อของจริงในคลังไม่ตรงกับยอดในระบบ)
- กด **"✅ ยืนยันปล่อยของ"** ระบบจะตัดสต๊อกตามจำนวนที่ปรับจริง และเปลี่ยนสถานะเป็น **จ่ายแล้ว**
- กด **"✕ ยกเลิกคำขอนี้"** ได้ถ้าคำขอนั้นผิดพลาด/ไม่ต้องการแล้ว (ไม่มีการตัดสต๊อก)
- การเติมสต๊อก (โดยแอดมิน) ยังคงตัดยอด/บวกสต๊อกทันทีเหมือนเดิม ไม่ต้องผ่านขั้นตอนนี้

รายงานทุกหน้า (ฟุ่มเฟือย, การเบิก, รายแผนก) จะนับเฉพาะรายการที่ **"จ่ายแล้ว"** เท่านั้น ไม่รวมคำขอที่ยังรอปล่อยของ เพื่อให้ตัวเลขค่าใช้จ่ายตรงกับของที่ออกจากคลังจริง — หน้า **ประวัติ** ยังคงแสดงทุกสถานะ (รอปล่อยของ/จ่ายแล้ว/ยกเลิกแล้ว) ไว้เป็น log ตรวจสอบย้อนหลัง

## เช็คสต๊อก — ตรวจนับสินค้าประจำเดือน (เฉพาะแอดมิน)
แท็บ **"🧮 เช็คสต๊อก"** สำหรับตรวจนับสต๊อกจริงเทียบกับระบบ (เช่น เช็คทุกสิ้นเดือน):
- แสดงสินค้าทุกชิ้นพร้อมช่อง **"นับได้จริง"** (ค่าเริ่มต้น = ยอดในระบบ ให้แก้เฉพาะรายการที่นับได้ไม่ตรง จะได้ไม่ต้องกรอกทุกช่อง) มีค้นหา/กรองหมวดหมู่ช่วยให้หาสินค้าง่ายเวลาสินค้าเยอะ
- ใส่หมายเหตุได้ (เช่น "เช็คสต๊อกประจำเดือนกันยายน 2569")
- กด **"💾 บันทึกผลการเช็คสต๊อก"** — ระบบจะ **ปรับยอดคงเหลือให้ตรงกับที่นับจริงเฉพาะรายการที่มีผลต่าง** และบันทึกเป็นประวัติการเช็คสต๊อก 1 ครั้ง (ไม่กระทบรายการที่นับตรงกับระบบอยู่แล้ว)
- ด้านล่างมี **ประวัติการเช็คสต๊อก** ทุกครั้งที่เคยทำ คลิกแถวเพื่อดูรายละเอียดว่ารายการไหนมีผลต่างเท่าไหร่ พร้อมปุ่ม **"⬇ Excel"** ดาวน์โหลดรายงานของครั้งนั้นๆ ได้ทันที (มีทั้งสรุปและรายละเอียดในไฟล์เดียว)
- หน้าผู้ใช้งาน (ดาวน์โหลดฐานข้อมูลทั้งหมด) ก็รวมประวัติเช็คสต๊อกทั้งหมดไว้ในไฟล์ Excel ให้ด้วยแล้ว

## ข้อจำกัดที่ควรทราบ
- **อัปเดตไม่เรียลไทม์ 100%** — แอปจะดึงข้อมูลใหม่ทุก 8 วินาที (และดึงทันทีหลังทำรายการของตัวเอง) ถ้าเปิดหลายเครื่องพร้อมกันอาจเห็นข้อมูลช้ากว่ากันเล็กน้อย
- **รูปสินค้า** เก็บเป็นรูปบีบอัด (base64) ฝังอยู่ในข้อมูลสินค้าโดยตรง ไม่ได้แยกเก็บไฟล์ต่างหาก จึงไม่ควรใช้รูปที่มีรายละเอียดสูงมาก (ระบบย่อให้อัตโนมัติเหลือด้านยาวสุด 480px อยู่แล้ว)
- **ความปลอดภัย**: ลิงก์ Apps Script (`API_URL`) เป็นแบบเข้าถึงได้จากทุกคนที่มีลิงก์ (Anyone) เพื่อให้เว็บเรียกข้อมูลได้โดยไม่ต้องล็อกอิน Google ทุกครั้ง ระบบล็อกอินที่ทำไว้เป็นการกันในระดับแอปพลิเคชัน (เช็ค username/password ที่เก็บเป็น SHA-256 hash) ไม่ใช่การเข้ารหัสระดับเซิร์ฟเวอร์ เหมาะกับการใช้งานภายในองค์กรที่ไม่เปิดเผยลิงก์ Apps Script ต่อสาธารณะ ไม่ใช่ระบบความปลอดภัยระดับสูง หากต้องการความปลอดภัยที่สูงขึ้น (เช่น ผูกกับระบบ SSO ของโรงพยาบาล) แจ้งได้ครับ
- Google Apps Script มีโควตาการเรียกใช้งานต่อวันสำหรับบัญชี Gmail ฟรี (โดยทั่วไปเพียงพอสำหรับการใช้งานภายในหน่วยงานขนาดกลาง) หากใช้งานหนักมากอาจพิจารณาย้ายไปใช้ Google Workspace หรือฐานข้อมูลอื่นในอนาคต
